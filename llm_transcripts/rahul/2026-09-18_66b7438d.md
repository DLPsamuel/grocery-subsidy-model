## What the documents say, simply

**The question:** New York City wants to make groceries cheaper in Hunts Point/Longwood (Bronx Community District 2), one of its poorest, most food-insecure areas. If the city pays part of a grocery store's costs, how much money actually reaches residents? How much should the city spend? Which kind of store gives the most benefit per dollar?

**How the model answers it (the spec):**
1. **Where people shop.** Each household gives every nearby store a "satisfaction score" based on store type (supermarket > discount store > bodega), basket price and walking time. Households are split into low, mid and high income. Low-income households care much more about price. A logit formula turns those scores into the chance of shopping at each store.
2. **Subsidy becomes a lower price.** If the city gives a store `s` dollars a year (a tax break or rent subsidy, treated as the same thing), the store passes on part of it, θ ≈ 65%. That spreads across all its baskets: price cut = 0.65 × s ÷ baskets sold per year.
3. **Lower price becomes a benefit for residents.** A lower price makes that store more attractive. The "logsum" formula turns that into a dollar figure, **ΔCS**. It counts both the savings for existing shoppers and the gain for people who switch to the store.
4. **Goal 1:** try subsidy amounts from $0 up to the budget, and find the smallest one that clears both thresholds (a 5% price cut and at least $50K a year of benefit).
5. **Goal 2:** run Goal 1 for every candidate store, rank them by benefit, and check what share goes to low-income households.
6. **Sensitivity:** vary θ and price sensitivity, because the results depend heavily on them.

**Who does what:** Rahul handles store and business data, Chris handles consumer and policy parameters, and Samuel handles demographics and city data. The document marks one item as urgent: the list of grocery stores in CD2.

## Issues worth raising with the team

**1. The spec has drifted from the proposal:**
- The proposal compares two policies: FRESH (tax and zoning breaks) against N.Y.C. Groceries (city-owned stores selling about 30% below market). The spec models only a generic subsidy to an existing store, so that comparison is gone.
- The proposal's firm profit function (margin × quantity − fixed cost) isn't in the spec. Pass-through is simply assumed.
- The proposal says Phase 2 uses Gurobi. The spec uses simple ranking for one store, and Gurobi only if the team later picks more than one.

**2. The welfare unit looks wrong.** The logsum gives dollars per shopping trip, but the spec labels it dollars per household per year. It needs to be multiplied by trips per year (about 52). Without that, the benefit is understated by roughly 50×. That fits the worked example's odd result: a $100K subsidy producing only $126–$500 in benefit.

**3. The price-sensitivity values swamp everything else.** With 0.55 per dollar, a $6 price gap outweighs the supermarket bonus, so the model predicts about 0% of low-income households use the supermarket. The store-type bonuses should be tuned so predicted market shares match real ones.

**4. The example numbers are placeholders, not model output. Don't cite them.**
- The Goal 2 example table shows a $0.72 price cut, which matches a $100K subsidy. But the code gives each store the full $1.5M, which would mean about $10.78.
- Appendix B says the required subsidy drops "about 35%" as θ rises, but its own table shows about 52%.
- 5,900 households is far too low for CD2. Samuel's census pull should replace it.

**5. Smaller points:**
- Bodegas are given the cheapest basket ($30), although they're usually more expensive.
- The logit model assumes that when one store gets cheaper, it draws customers evenly from all the others. This isn't listed among the assumptions.

### 🤖 Claude  <sub>2026-09-18 15:31</sub>

The `git` command is a program on your Mac that knows how to talk to GitHub's servers over the internet. Running `git clone <url>` works like this:

1. **The URL is an address.** `https://github.com/OWNER/REPO.git` tells git which server to contact (github.com) and which repository to ask for.
2. **Git talks to GitHub the way a browser talks to a website.** It uses the same HTTPS protocol your browser uses, or SSH if the URL looks like `git@github.com:OWNER/REPO.git`. GitHub runs a git server that understands these requests.
3. **GitHub checks whether you're allowed in.**
   - **Public repo:** anyone can read it, so no login is needed.
   - **Private repo:** git has to prove who you are. It uses a saved credential, which is usually a personal access token, an SSH key, or a login stored by `gh auth login`. On a Mac these are usually kept in Keychain, so you only enter them once.
4. **GitHub sends the data.** That's the full project history (every commit), compressed. Git unpacks it into a folder and checks out the latest version of the files.

The command line isn't special here. GitHub Desktop and VS Code's "Clone Repository" button run this same `git` program behind the scenes. The CLI just lets you call it directly.

## Why Git LFS

GitHub **warns** on files larger than **50 MB** and **rejects** files larger than **100 MB** when stored as normal git blobs.

This repo uses [Git Large File Storage (LFS)](https://git-lfs.com/) for large raw artifacts so the team can share the same files without hitting that limit.

### Files tracked with LFS in this repo

| Path | Role |
|------|------|
| `data/stores/snap_retailers_us_raw.csv` | US-wide SNAP retailer raw extract (~91 MB) |
| `data/stores/snap_retailers_raw_sample_cols.csv` | Related large SNAP CSV (~91 MB) |
| `data/stores/**/*.zip` | Zip archives under stores (e.g. SNAP locator dumps) |

Smaller **CD2-filtered** CSVs/GeoJSONs (ACS, BLS, `snap_bronx_cd2.csv`, etc.) stay in **normal git** — do not put every file on LFS.

Patterns live in the repo-root [`.gitattributes`](../.gitattributes).

   - **N.Y.C. Groceries:** savings = 30% × core-basket sales. The city pays the discount minus the store's own profit, plus a small operator fee. Each public dollar therefore reaches shoppers almost one-for-one.
   - **FRESH:** the city gives a tax break. Savings = pass-through × tax break, where pass-through means the share of the break that reaches shelf prices. It's uncertain because nothing in FRESH requires lower prices, and a break on fixed costs like rent and tax doesn't push prices down in theory. Test 0 to 100% as scenarios.

That gives you:
- a savings-vs-subsidy curve for each policy (Q1),
- the subsidy needed for a savings target (Q2),
- how the cost changes with store type (Q3),
- the share of savings that goes to low-income households.

It's buildable in about a week of Python. A small Gurobi budget-allocation model stays as an optional extra, which still covers the proposal's promised solver phase. None of Samuel's data collection is wasted.

## Why the sources support this change

- **FRESH:** it costs about **$110–150K per store per year**, and the Comptroller's evaluation found **no evidence it lowered prices**.
- **New stores:** in Pittsburgh and Philadelphia, few residents made a new supermarket their main store.
